# 临时及混合补单文件夹人工登记

- 目标：用户在外部库存系统完成出库后，按文件夹独立登记；参考订单可为空或多个，不参与正式订单归属。
- 状态：已完成实现、发布门禁、正式签名安装和安装版入口验收。
- 约束：不操作真实出库、不登记当前生产文件夹；保留原订单材料、五金、生产、出货事实；保留已有工作树修改。
- 方案：复用 temporary_orders，增加可选参考订单；普通临时及满足补单条件的混单提供人工登记。已选人工方式的文件夹继续独立扫描，禁止进入正式订单预览/自动出库路径。
- 扫描：人工完成后三天只观察 XML；观察期发现变化后持续待处理；相同内容重复登记不延长观察期。
- 步骤：后端与迁移 → 公用登记界面/CLI → 隔离回归 → 文档 → 发布门禁 → 一次构建 → 正式签名安装/入口验收。
- 验证：无订单/单订单/混单、已出货父订单、重复登记、XML 变化、到期、事务失败、正式事实不变和库存调用为零。
- 补单判定：新的非标准 Server 文件夹，名称关联的每个订单在最近同步的 AIMES 事实中存在且所有工厂单已出库；新工厂单尚未出库时恢复正常处理。
- 剩余决策：无。参考订单和外部出库单号均可留空；登记时间作为本次完成记录时间。
