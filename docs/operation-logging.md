# 操作日志

PP FlowHub 的操作日志默认开启，文件位于 `~/Documents/pp-flowhub/data/operation-log.jsonl`。

每行是一个独立 JSON 事件，包含本地时间、事件名称、组件、操作/运行 ID、步骤说明和脱敏后的上下文。SwiftUI、Python 后台、Playwright 和 SQLite 写入事件共用同一文件，并通过操作 ID 串起一次完整任务。

日志用于错误回溯：可以从某个操作的 `operation.started` 开始，按时间查看后台步骤和网页控件动作，再定位到配对的 `operation.completed` / `operation.failed`，或后台的 `backend.command.completed` / `backend.command.failed`。完成事件带有 `duration_seconds`，因此可以区分用户点击到界面收尾的总用时，与后台命令自身用时。日志写入失败不会阻断业务操作。

耗时按业务阶段记录，而不是把每一条 SQL 当作一个“步骤”：这避免高频数据库日志既影响性能又淹没真正的业务动作。当前阶段包括：

- Server 扫描：读取并比对 Server 文件、解析并校验变化材料文件、写入扫描元数据和快照。
- Server 预览/确认：复制中央数据库到内存预览、解析 Server 变化、组装预览结果；确认时校验预览并提交中央数据库事务。
- 库存出货：SwiftUI 启动与收尾、后台准备、库存网页操作、回写中央数据库；网页进度会在 Node/Playwright 运行时实时写入日志，包含相对秒数、页面路径及阶段开始/完成信息。
- 订单列表刷新：作为独立操作记录，不能覆盖前一笔库存出货的总用时。

隐私边界：不记录用户名、密码、备注、语音原文、文本框输入值、网页输入值、网页全文或附件原文。网页日志只保留必要的页面路径和控件动作；数据库日志只记录数据库、写入动作和表名，不记录绑定参数或业务数据值。

设置页的“记录用户操作和后台执行步骤”开关会持久化到 `settings.json`。关闭前会记录关闭动作，关闭后停止新增事件；再次开启后恢复记录。

设置页的“查看”按钮会读取同一份 JSONL 日志，并在弹窗中以“时间 + 操作内容”显示。查看页不展示事件类型、组件、操作 ID 或脱敏上下文，避免把内部诊断字段直接暴露给日常使用者；最新记录显示在顶部。
